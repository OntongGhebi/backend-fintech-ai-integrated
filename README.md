## Description

[Nest](https://github.com/nestjs/nest) framework TypeScript starter repository.

## Project setup

```bash
$ npm install
```

## Testing subscription checkout in Swagger

Before testing checkout, configure `DATABASE_URL`, `MIDTRANS_SERVER_KEY`, and
`MIDTRANS_CLIENT_KEY` in `.env`. Use Midtrans Sandbox credentials and keep
`MIDTRANS_IS_PRODUCTION=false`.

Apply the database migrations and seed an active test plan:

```bash
npx prisma migrate deploy
npm run db:seed
```

Start the API and open Swagger at `/docs` (the API prefix is `/api/v1`). Then
use the same authenticated user for these requests:

1. `GET /api/v1/plans` and confirm that `PREMIUM_MONTHLY` is active.
2. `POST /api/v1/subscriptions/trial` with
   `{"planCode":"PREMIUM_MONTHLY"}`. Copy the returned subscription `id`.
3. `POST /api/v1/payments/checkout` with
   `{"subscriptionId":"<subscription-id>"}`.

The checkout response includes the Midtrans Snap token and Sandbox redirect URL.
If the account has already used its trial or has a current subscription, use a
different account before starting the trial.

## Compile and run the project

```bash
# development
$ npm run start

# watch mode
$ npm run start:dev

# production mode
$ npm run start:prod
```

## Run tests

Create `backend/.env.test` using the example below and set `DATABASE_URL` to a
dedicated PostgreSQL test database. Do not point it at development or production
data. Apply the project's migrations to that database before the first run.

```bash
# unit tests
$ npm run test

# e2e tests
$ npm run test:e2e

# run one e2e file
$ npm run test:e2e -- test/dashboard.e2e-spec.ts

# test coverage
$ npm run test:cov
```

The E2E scripts load `.env.test` before starting Jest and run serially
(`--runInBand`) to reduce contention from multiple Nest application instances
and database operations. The test environment file is excluded from version
control.

## Deployment

When you're ready to deploy your NestJS application to production, there are some key steps you can take to ensure it runs as efficiently as possible. Check out the [deployment documentation](https://docs.nestjs.com/deployment) for more information.

If you are looking for a cloud-based platform to deploy your NestJS application, check out [Mau](https://mau.nestjs.com), our official platform for deploying NestJS applications on AWS. Mau makes deployment straightforward and fast, requiring just a few simple steps:

```bash
$ npm install -g @nestjs/mau
$ mau deploy
```

With Mau, you can deploy your application in just a few clicks, allowing you to focus on building features rather than managing infrastructure.
